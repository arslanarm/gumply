# Если что-то не так, и где лежат ваши данные

## Где лежат ваши данные

**Ваши заметки — в папке хранилища**, обычными файлами:

| В хранилище | Что это |
|---|---|
| `*.md` | ваши страницы; подстраницы лежат в папке с именем страницы |
| `*.canvas` | ваши доски |
| `*.base` | ваши базы данных |
| `attachments/` | изображения и файлы, которые вы добавили |
| `.trash/` | удалённые страницы — пока вы не очистите Корзину |
| `.gumply/history/` | [история версий](version-history.md) |
| `.gumply/conflicts/` | резервные копии, которые делает **Оставить мою**, чтобы вторая сторона конфликта не потерялась |
| `.gumply/types.json`, `graph.json` | типы свойств (если нет `.obsidian`) и настройки графа |
| `.gumply/mcp.json`, `mcp-log.jsonl` | доступ [ИИ-приложений](ai-apps.md) и журнал их действий |
| `.obsidian/` | настройки Obsidian: Gumply их читает (а пишет только тип свойства, который вы меняете) |

**Собственные настройки настольного приложения** (список хранилищ, размер окна, язык и тема) лежат вне хранилищ:

- Linux: `~/.config/Gumply/gumply-desktop.json`
- Windows: `%APPDATA%\Gumply\gumply-desktop.json`
- macOS: `~/Library/Application Support/Gumply/gumply-desktop.json`

Чтобы сделать резервную копию заметок, копируйте папку хранилища. Чтобы перенести их на другой компьютер — тоже.

## «Эта страница изменилась на диске»

Другая программа (или другое окно Gumply) изменила страницу, пока у вас были несохранённые правки. Gumply никогда не перезаписывает её молча:

- **Загрузить заново** покажет их вариант и отбросит ваши несохранённые правки;
- **Оставить мою** сохранит ваш вариант, а их — положит резервной копией в `.gumply/conflicts/`.

Обе стороны есть и в [истории версий](version-history.md) страницы.

## Пропала удалённая страница

Загляните в **Корзину** внизу боковой панели. Если страницу удалили в другой программе, её последние версии могут быть в **Корзина → Ранние версии удалённых страниц**.

## Появилась конфликтующая копия

Программа синхронизации сохранила обе стороны правки, сделанной на двух устройствах. См. [Синхронизация с другими программами](sync-with-other-apps.md).

## ИИ-приложение не подключается

См. раздел о проблемах в [docs/mcp.md](../../mcp.md#troubleshooting) (на английском). Чтобы увидеть, что именно происходит, когда ИИ-приложение запускает Gumply, задайте в настройках этого приложения для Gumply переменную `GUMPLY_MCP_TRACE=/путь/к/trace.log` — в файл запишется каждый шаг.

## Приложение не запускается

- **AppImage в Linux:** нужен FUSE 3 (`fusermount`). В Ubuntu: `sudo apt install fuse3`. Если его нет, об этом скажет и окно «ИИ-приложения».
- **Windows и macOS:** при первом запуске нужно одно подтверждение, потому что приложение пока не подписано. См. [Начало работы](getting-started.md#установка).

## Сообщить о проблеме

Создайте issue на [GitHub](https://github.com/arslanarm/gumply/issues). Напишите, что вы делали, чего ожидали и что произошло, а также свою систему и версию Gumply (**Справка → О Gumply**). Не прикладывайте заметки, которые не хотели бы делать публичными: issues видны всем.
